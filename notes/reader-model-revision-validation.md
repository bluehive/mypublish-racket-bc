# 想定読者モデルを本文へ持ち込まないための改稿

更新日: 2026-11-03（JST）

## 編集上の方針

想定読者モデルは説明の細かさ、用語の導入順、例の大きさを判断するために使う。本文、タイトル、紹介文では、そのモデルを読者本人の属性として語らない。操作の説明は、別の教材やプログラミング環境を使った経験に頼らず、その場で読める例から組み立てる。

本文の学習手順は「具体例 → 用語 → 小さい式 → 動作の追跡 → テスト」とする。スタック、リスト、関数、条件分岐、再帰、check-expectの説明は維持し、経験に依存する比較を、式や値の変化の直接の説明へ書き換えた。

## 変更範囲

- はじめに: 読者への経験の問いかけをやめ、電卓の目標から導入。画面の領域、入れ子の式、道具の読み込みを、その役割と実例から説明。インストールの案内も利用環境を限定しない表現に変更。
- 第1章: スタックとリストの順序、引数の受け渡し、元のリストと新しい値、ifの二通りの分岐を直接説明。
- 第2章: 計算に使う二つと残る数、condの条件の順序を、掲載例だけで追えるように変更。
- 第3章: 再帰を「最初の一つと残り」に分ける説明から導入。次の呼出しへ渡す入力とスタックを明示。
- おわりに: 操作の振り返りと紙上の確認方法から復習を構成。
- config・README: 読者属性を示す紹介を、学ぶ内容と進め方の紹介へ変更。

前回のPR #2に添付した検証・採点メモは、その時点の記録として保存する。過去の評価や読者への呼びかけを、今回の方針に適合したという根拠には使わない。今回の判定は [別エージェントの新規評価](reader-model-librarian-review.md) を参照する。

## 確認方法

1. books以下の全5本文・config・READMEを検索し、年齢や特定のツール経験に言及する記述が残っていないか確認。
2. 検索だけでは判断できない、別の教材への暗黙の比較や未説明語を、司書ペルソナの別エージェントが通読して確認。
3. 元のコードと本文のracketコードブロックを変更していないことを比較し、本文中の実行例をRacketで再実行。
4. 全5本文を再結合して、生成原稿にも旧表現が残らないことを確認。
5. front matter、コードフェンス、リポジトリ内リンク、git diff --checkを確認。

検証結果はPR起票前に以下へ追記する。DrRacketのGUI操作と実際の学習者による読解の観察は、この検証とは別に扱う。既知の出版工程の問題を、本文修正の成否と混同しない。
