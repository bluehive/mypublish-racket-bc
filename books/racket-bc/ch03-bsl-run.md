title: "第3章 命令の並びを一つずつ実行する"
---

一回の計算ができたら、「2を積む、3を積む、足す、答えを見る」をまとめて実行してみましょう。この章では、**入力・スタック・出力**の三つを区別します。後半に少し長い関数が出ますが、まずは表を紙で追い、次にコードへ進めば大丈夫です。

第2章で保存した`ch02-arith.rkt`を使います。Runしてから短い式を対話エリアで試せます。以下の定義は完成ファイルに既にあるので、重ねて貼らないでください。追加テストは、定義エリアの最後の`(test)`より前へ置きます。

## 3.1 入力・スタック・出力を分けよう

- **入力**：これから実行する数や命令の並び。「やることリスト」に当たります。
- **スタック**：計算途中の数を積む場所です。左端がトップです。
- **出力**：`"p"`で記録した、あとで見る答えの並びです。最終スタックとは別です。

入力の一項目を**トークン**と呼びます。名前は難しそうですが、ここでは数の`2`や、文字列の`"+"`・`"p"`一つのことです。

```racket
(list 2 3 "+" "p")
```

これは四つのトークンを順に並べた入力です。`"2 3 + p"`という一つの文字列を渡す方法ではありません。数値の`2`と文字列の`"2"`も別の値です。この電卓では数は数値、命令は文字列で渡します。

完成コードの`run`（ラン）は、「入力を順番に実行する」という本書の関数です。引数は二つで、**入力のリスト、開始時のスタック**の順に渡します。

```racket
(check-expect (run (list 2 3 "+" "p") '()) (list 5))
```

二つ目の`'()`は、空のスタックから始める指定です。テストの予想は、`p`で記録した出力の`(list 5)`です。まず実際の計算部分を対話エリアで試してみましょう。

## 3.2 stepは一つの指示だけを担当する

`step`（ステップ）は、一つのトークンとスタックを受け取り、**次のスタック**を返します。入力全体を進める仕事と分けると、確かめる範囲を小さくできます。

| トークン | 前のスタック | 次のスタック | すること |
|---|---|---|---|
| `7` | `(list 3)` | `(list 7 3)` | 数を積む |
| `"+"` | `(list 3 2)` | `(list 5)` | 二つを足す |
| `"d"` | `(list 7 3)` | `(list 7 7 3)` | トップを複製 |
| `"r"` | `(list 7 3)` | `(list 3 7)` | 上の二つを交換 |
| `"c"` | `(list 7 3)` | `'()` | 全消去 |
| `"p"` | `(list 7 3)` | `(list 7 3)` | スタックは変えない |

`"d"`はduplicate（複製）、`"r"`は上の二つの順序を逆にする命令、`"c"`はclear（消去）です。第1章の操作を、短い命令名で選べるようにします。`p`の記録は後で`run`が担当するので、`step`ではそのままです。

```racket
(define (step t s)
  (cond [(number? t) (push t s)]
        [(string=? t "+") (binop "+" s)]
        [(string=? t "-") (binop "-" s)]
        [(string=? t "*") (binop "*" s)]
        [(string=? t "/") (binop "/" s)]
        [(string=? t "d") (push (top s) s)]
        [(string=? t "r") (push (top (pop s)) (push (top s) (pop (pop s))))]
        [(string=? t "c") '()]
        [(string=? t "p") s]
        [else (error "unknown token")]))
```

`t`はトークン、`s`はスタックの仮の名前です。`number?`は数値かどうかを調べます。`cond`は最初に当てはまった行で決まるので、数値ならその場で`push`を使い、後の文字列の比較には進みません。入力を数値か文字列に限る約束が、ここで役立ちます。

文字列なら、どの命令か順に調べます。最後まで見つからない場合は、`"unknown token"`（知らない命令）というエラーです。第2章の`apply-op`には、ここで選んだ四つの計算記号だけが渡ります。

```racket
(check-expect (step 7 '()) (list 7))
(check-expect (step "*" (list 3 4)) (list 12))
(check-expect (step "p" (list 12)) (list 12))
```

## 3.3 残りを自分に頼む「再帰」

Scratchでは「繰り返す」ブロックで同じ処理を進めたことがあるかもしれません。ここでは、**一つ処理したら、残りの仕事を同じ関数へ頼む**方法を使います。関数の定義の中でその関数を呼ぶことを、**再帰（さいき）**と呼びます。

たとえば、入力が`(list 2 3 "+")`なら、次のように小さくします。

| 残っている入力 | 現在のスタック | 次にすること |
|---|---|---|
| `(list 2 3 "+")` | `'()` | 2を処理して、残りを頼む |
| `(list 3 "+")` | `(list 2)` | 3を処理して、残りを頼む |
| `(list "+")` | `(list 3 2)` | 足して、残りを頼む |
| `'()` | `(list 5)` | 入力がないので終わる |

**一回ごとに残りが一つ減ること、空になったら終わること**がポイントです。「ずっと自分を呼び続ける」という意味ではありません。なお、この例には`p`がないので、計算後のスタックに5があっても、出力は空です。

## 3.4 runを三つの場合に分ける

まず言葉で整理します。

1. 入力が空なら、これから記録する値はないので空リストを返す。
2. 先頭が`"p"`なら、今のトップを記録する。スタックを変えずに残りを実行する。
3. それ以外なら、`step`で一つ処理した次のスタックを使い、残りを実行する。

これをコードにしたものが、完成ファイルの次の関数です。

```racket
(define (run ts s)
  (cond [(empty? ts) '()]
        [(and (string? (first ts)) (string=? (first ts) "p"))
         (cons (top s) (run (rest ts) s))]
        [else (run (rest ts) (step (first ts) s))]))
```

`ts`はまだ実行していない入力リスト、`s`は現在のスタックです。第1章の三つの操作を使っています。`first`で次の指示を読み、`rest`で残りの指示を得て、`cons`で出力の先頭に値を付けます。**同じリスト操作でも、入力に使うか、出力に使うかで役割が違う**ことに気を付けましょう。

二つ目の条件に出る`string?`は、文字列かどうかを調べます。`and`（アンド）は「両方の条件がはい」を表します。左が`#false`なら、右は計算しません。そのため、先頭が数値のときに、文字列用の`string=?`へ渡すことを避けられます。

三つ目の行は、`(step (first ts) s)`で次のスタックを作り、その答えを、`(rest ts)`と一緒に次の`run`へ渡しています。Scratchで変数の内容を更新して繰り返す代わりに、**次の状態を引数で渡す**方法です。

最初の行で空を調べるので、入力がないのに`first`を使うことも避けています。再帰で呼ぶ箇所は、どちらも`(rest ts)`です。有限の入力なら、最後は空になります。

## 3.5 pの答えは、どう順番に並ぶ？

`p`の行の`cons`を、小さい例で確かめます。入力が`(list 7 "p" 8 "p")`なら、7を記録し、次に8を積んで記録します。

```text
最後のp: (cons 8 '())              → (list 8)
その前のp: (cons 7 (list 8))       → (list 7 8)
```

残りの仕事の答えが返ってきたら、今の値をその前に付けます。そのため、出力が逆順にはなりません。途中にリストを直接書き換える操作はありません。この図は答えの組み立てを説明しており、プログラムが指示を後ろから実行するという意味ではありません。

この違う二つの数が7、8の順に並ぶことも、テストで確認できます。

```racket
(check-expect (run (list 7 "p" 8 "p") '()) (list 7 8))
```

次は入力全体を表で追います。「ここまでの記録」は手で理解するための欄です。実際の`run`には、この記録をためる別の引数はありません。

| 処理した指示 | 次のスタック（左がトップ） | ここまでの記録 |
|---|---|---|
| 開始前 | `'()` | `'()` |
| `5` | `(list 5)` | `'()` |
| `"d"` | `(list 5 5)` | `'()` |
| `"*"` | `(list 25)` | `'()` |
| `"p"` | `(list 25)` | `(list 25)` |
| `1` | `(list 1 25)` | `(list 25)` |
| `"-"` | `(list 24)` | `(list 25)` |
| `"p"` | `(list 24)` | `(list 25 24)` |

```racket
(check-expect (run (list 5 "d" "*" "p" 1 "-" "p") '())
              (list 25 24))
```

`run`が返すのは最終スタックの`(list 24)`ではなく、出力の`(list 25 24)`です。`p`はスタックから数を取り除かないので、記録した25を、そのあとの引き算にも使えます。

## 3.6 小さいテストで確かめる

追加テストは、完成ファイルの最後の`(test)`の前へ置きます。実際の計算を対話エリアで試してから、予想をテストにしてもよいでしょう。

```racket
(check-expect (run '() '()) '())
(check-expect (run (list 2 3 "+") '()) '())
(check-expect (run (list 7 "p" "p") '()) (list 7 7))
(check-expect (run (list 9 "c" 4 "p") '()) (list 4))
(check-expect (run (list 3 2 "/" "p") '()) (list 3/2))
(check-error (run (list "p") '()) "stack empty")
(check-error (run (list 1 "+") '()) "stack empty")
(check-error (run (list "?") '()) "unknown token")
```

二つ目は、計算できても`p`がないので、出力が空になる例です。エラーの三つは、順に「見る数がない」「計算する数が足りない」「知らない命令」です。

本書の「出力」は最後に返すリストなので、途中でエラーになれば、それ以前の`p`の値も画面へ順々には出ません。たとえば`(run (list 7 "p" "?") '())`は、7を表示してから止まるのではなく、全体としてエラーです。

## 3.7 確かめ問題

1. `(run (list 8 2 "/" "d" "+" "p") '())`の出力を予想しましょう。
2. `(run (list 8 2 "r" "-" "p") '())`では、交換によって引き算がどう変わるでしょう。
3. 再帰がいつまでも続かないのは、入力の何が変わるためでしょう。

**答え**：1は`(list 8)`。8÷2で4、複製して4＋4です。2は`(list -6)`。交換後のスタックは`(list 8 2)`なので2−8です。3は、呼ぶたびに残りの入力が一つ減り、空になったら終えるためです。

最後に、自分で短い入力を一つ作り、予想を`check-expect`に書いて試してみましょう。分からなくなったら、入力、スタック、出力を三列に分けて書き直すと、つまずいた場所を見つけやすくなります。
